A CLOSER LOOK AT THE PRODUCT

What Odoo AI Integration actually includes

A controlled AI-to-ERP connection built around real business permissions, not unrestricted database access.

01

MCP tool interface

Exposes typed tools for agent discovery and approved ERP data requests.

02

Record discovery

Supports finding business models and permitted entities without granting arbitrary access.

03

Entity resolution

Maps an agent's business reference to the matching ERP record through controlled lookup logic.

04

Structured queries

Retrieves permitted business fields and records through the platform's application data layer.

05

Read-only aggregation

Supports bounded summaries and aggregations without changing business records.

06

Permission-aware access

ERP user permissions, field rules and company boundaries remain in force for business reads.

07

Separated gateway

A dedicated gateway performs governed ORM reads rather than putting unrestricted database operations in the agent.

08

Test-environment evidence

Dated integration records describe successful agent-side lookups and permission-denial behavior in a Test environment.

TECHNICAL DEEP DIVE

Architecture and stack

AI client

An agent requests business information through typed MCP tools.

Connector

Python tools handle discovery, entity resolution, queries and aggregation.

Read gateway

A separate application gateway mediates approved Odoo operations.

ERP data

Odoo ORM returns records within the configured identity and business permissions.

Technology stack

Python 3.11 · Model Context Protocol · Odoo ORM · Typed schemas · pytest · Ruff · mypy

Data and access controls

The connector is read-only for business data. Odoo application authorization remains active for record, field and company access. No unrestricted SQL reporting is exposed to the agent.

Verification status

Documented test-environment checks include permitted reads and denied access. Production authorization and full module completion were not established.

Source: connector README, Python manifest and interface-contract documentation.

Why it matters

AI agents need relevant ERP context, but general access would bypass normal business permissions.

The solution

A read-only MCP connector and Odoo gateway for permitted record lookups and aggregation, respecting ERP access rules and configured company scope.

What it covers

  • MCP-based integration
  • Read-only record discovery and reporting
  • Permission-aware Odoo access

My involvement

AI-to-ERP integration, controlled query design and business-system access boundaries.
